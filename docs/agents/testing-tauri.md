# Testing Tauri code

Rust lives in `src-tauri/`. Run `cargo fmt`, `cargo clippy --all-targets -- -D warnings` and `cargo test` there; the `rust` job in `ci.yml` runs the same.

## Gotchas

- `tauri::generate_context!` needs `dist/` to exist at compile time (`mkdir -p dist` if `pnpm build` has not run).
- `tauri-build` validates the names in `capabilities/*.json`, so a wrong permission fails `cargo build` / `cargo clippy`. Look names up in `~/.cargo/registry/src/*/tauri-plugin-<name>-*/permissions/autogenerated/commands/`.
- `confirm` and `ask` of `plugin-dialog` run through the `message` command: grant `dialog:allow-message`.
- Own `#[tauri::command]`s need no capability; they accept any path, so keep them small and test them with plain `cargo test` on temp directories (`tempfile`).
- `plugin-fs` reads only paths the dialog returned. A path the app builds itself (a typed name plus `.tpsheet`) is out of scope: use an own command.
- Raw bytes go over `invoke(cmd, bytes, { headers })`; header values must be ASCII, so percent-encode paths.

## Frontend tests

Test the Tauri `FilePort` (`src/worksheet-file/tauri-port.ts`) with `vi.mock` on `@tauri-apps/api/*` and `@tauri-apps/plugin-*`. `getCurrentWindow().setTitle` must return a promise in the mock.

Native dialogs, the window title and the real file system cannot be driven automatically. Verify them by hand under `pnpm tauri dev` and say in the PR that it was manual.
