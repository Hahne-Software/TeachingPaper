# Asset Catalog for Worksheets

## Motivation

A good Worksheet needs cartoons, pictures, clip art, graphics and maps. Teachers spend time searching for them and often cannot tell if they may use them. An **Asset Catalog** built into TeachingPaper offers ready-to-use **Assets** whose licenses are already checked.

Proposed domain terms (add to `GLOSSARY.md` once implemented):

- **Asset**: an image file (cartoon, picture, clip art, graphic, static map) offered in the Asset Catalog, together with its license data.
- **Asset Catalog**: the hosted, searchable collection of Assets that teachers can insert into a Worksheet.

## Findings

### Prerequisites in the app

- ADR-0003 already prepared for this: a Worksheet File is a ZIP container, and `media/` is reserved for embedded files. No Block Type uses it in Format Version 1.0.
- There is no image Block Type yet. One is the prerequisite for the Asset Catalog. It changes the format spec, the XSD and the examples (`docs/format/worksheet-format.md`).

### Embed, don't link

- Inserting an Asset copies the file into the Worksheet File's `media/`. The Worksheet stays self-contained: it works offline, can be passed on, and does not depend on the catalog server being reachable.
- The app fetches through the Rust side and caches thumbnails locally. This touches Tauri capabilities/CSP (see `docs/agents/testing-tauri.md`).
- Print quality: prefer SVG for clip art and maps. Photos need enough resolution for 300 dpi at the printed size.

### Hosting

- **Cloudflare R2** (S3-compatible, no egress fees) stores the files.
- A **Cloudflare Worker** sits in front. No public bucket URL.
  - Catalog API: search, tags, Subject, Grade Level. The index lives in D1 or a generated JSON file.
  - Serves thumbnails for browsing and the original only when an Asset is inserted.
  - Access control: at first only abuse protection (rate limiting, maybe an app API key). Accounts are not needed while the catalog is free.
- Curation at first by an upload script that writes file and metadata to R2/D1. An admin UI only becomes necessary when others contribute.

### Business model

- The catalog is free at first.
- Paid packs may follow later, with pictures and material where the license allows resale. Each Asset should carry a `pack`/`tier` field from the start. The Worker can then unlock packs later without remodelling the catalog.

### Content sources

- Stage 1: curated by the maintainer.
- Stage 2: commissioned illustrations (the cleanest licensing).
- Stage 3: contributions from teachers. This needs moderation, a declaration of rights on upload, and a takedown process.
- Good sources:
  - CC0/public domain: Openclipart, Natural Earth (maps)
  - OpenStreetMap: ODbL, requires "© OpenStreetMap contributors"
- Unsuitable sources:
  - As far as we know, Pixabay and Unsplash forbid compiling their content into a similar or competing service, so it cannot be rehosted. Verify before deciding.
  - Wikimedia Commons has mixed licenses and needs a check per file.
- The German teaching exception §60a UrhG covers the teacher, not us as a distributor.

### Licenses and attribution

- Each Asset carries license data in the catalog: license as an SPDX ID (`CC0-1.0`, `CC-BY-4.0`, `ODbL-1.0`, ...), author, source URL, and whether attribution is required. It is checked once during curation, not in the app.
- Attribution is required for everything that is not CC0/public domain (or our own content).
- The image Block stores the license data in the Worksheet File, so attribution survives sharing the file. Format change: license/author/source attributes on the image Block.
- Rendering adds the credit line automatically to the printed/PDF Worksheet, either under the image or collected at the page foot. Teachers can optionally fill the same fields for images they insert themselves.

### Maps

- At first only static maps, as ordinary Assets (Natural Earth is a good public-domain base).
- Remember for later: a configurable **map Block Type** for geography lessons. The teacher picks the area, layers and labels, based on OSM/Natural Earth data, with the attribution handled automatically. This is a separate idea once the image Block exists.

## Open questions

- Credit line placement: under each image, or collected per Page or Worksheet?
- Catalog index: D1 or a static JSON file generated by the upload script?
- Does the app need an API key at all while the catalog is free, or is Worker-side rate limiting enough?
- Search language: German tags only, or multilingual from the start?
- Catalog browser UI: its own panel next to the Block Palette, or a dialog opened from the image Block?
- Which terms do we need for teacher contributions (rights declaration, takedown)?
